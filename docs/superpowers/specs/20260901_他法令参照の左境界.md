# 他法令参照の左境界を正式名称で確定する（設計）

- Issue: [#271](https://github.com/SlashNephy/surasura-roppou/issues/271)
- 前提: [#200](https://github.com/SlashNephy/surasura-roppou/issues/200) で他法令参照をリンク化、[#268](https://github.com/SlashNephy/surasura-roppou/issues/268) で法令番号から lawId を非同期解決

## 背景

法令番号の括弧書きを手掛かりに辞書外の法令名を拾う経路（`readFreeLawName`）は、左境界を区切り文字だけで決めている。そのため先行する語句を飲み込む。

```
入力: 附則第九条中農業協同組合法（昭和二十二年法律第百三十二号）第十一条
下線: 中農業協同組合法（昭和二十二年法律第百三十二号）第十一条
期待: 農業協同組合法（昭和二十二年法律第百三十二号）第十一条
```

逆に、境界文字の `、` が正式名称の内側にある法令では切りすぎる。

```
正式: 育児休業、介護休業等育児又は家族介護を行う労働者の福祉に関する法律
検出: 介護休業等育児又は家族介護を行う労働者の福祉に関する法律
```

## 測定した前提（2026-09-01）

法令 14 件（民法・会社法・労働基準法・原子力災害対策特別措置法ほか）の本文から法令番号付きの参照 1,233 件を採取し、e-Gov のカタログ 9,551 件が持つ正式名称を正解として現在の左スキャンと突き合わせた。

| 結果                             | 件数 | 割合 |
| -------------------------------- | ---: | ---: |
| 境界が正しい                     |  765 |  74% |
| 飲み込み（本件）                 |  197 |  19% |
| 切りすぎ                         |   42 |   4% |
| その他（法令が改称済み）         |   29 |   3% |
| 正解不明（改正法などカタログ外） |  200 |    — |

飲み込まれた先行語句に規則性は無い。

```
[中] + 商業登記法
[の規定による改正前の] + 電気事業法
[成年被後見人に宛てた郵便物又は] + 民間事業者による信書の送達に関する法律
[当該発電用原子炉の設置の工事について最初に] + 原子力規制委員会設置法
```

参照された法令番号の種別は 1,222 件が法律、政令は 4 件（0.3%）だった。

## 決定事項

| 論点                                     | 決定                                                                                        |
| ---------------------------------------- | ------------------------------------------------------------------------------------------- |
| 境界の決め方                             | 法令番号から引いた**正式名称**の完全一致で決める                                            |
| 正式名称が引けない・一致しないとき       | 現在の左スキャンへフォールバックする。下線が長いことより無リンクのほうが損失が大きい        |
| 表記ゆれの吸収                           | しない。完全一致のみ。正規化すると長さが変わり、開始位置の算出が狂う                        |
| 政令（導出経路）の正式名称               | カタログのキャッシュにあれば使う。無ければフォールバック。追加のネットワーク要求は出さない  |
| 漢字ガード                               | 法令番号を伴わない参照に限定する                                                            |
| 助詞・活用語尾を剥がすヒューリスティック | 採らない。`による` は `民間事業者による信書の送達に関する法律` の内側にあり、正式名称を削る |

## 設計

### 1. 解決結果に正式名称を載せる（`src/core/jump/law-number-resolver.ts`）

`LawNumberResolver.resolve` の戻り値を lawId 単体から構造体へ変える。

```ts
export interface ResolvedLawNumber {
  lawId: string;
  title?: string; // 正式名称。導出経路でカタログに無い場合は載らない
}

export interface LawNumberResolver {
  resolve(
    parsed: ParsedLawNumber,
    options?: { signal?: AbortSignal },
  ): Promise<ResolvedLawNumber | undefined>;
}
```

正式名称の入手経路は 3 つある。いずれも追加のネットワーク要求を伴わない。

- e-Gov への問い合わせ: 応答の `law.title` をそのまま使う
- カタログのキャッシュ: `LawCatalogEntry.title` を使う。索引を `Map<string, string>`（キー → lawId）から `Map<string, ResolvedLawNumber>` へ変える
- 導出経路（政令）: カタログの索引を引き、あればその正式名称を載せる。無ければ lawId だけを返す

導出経路がカタログを読むようになるため、`resolve` はカタログの読み込みを待つ。読み込みは起動から一度だけで、失敗しても best-effort で空の索引を返す既存の扱いを変えない。

### 2. 対応表の型を変える（`src/app/use-cross-law-numbers.ts` ほか）

`ReadonlyMap<string, string>` を `ReadonlyMap<string, ResolvedLawNumber>` へ変える。値の意味が lawId から「解決した法令」に変わるため、`lawIdByLawNumber` を `lawByLawNumber` へ改名する。

通り道は次のとおり。

```
use-cross-law-numbers → law-viewer-page → LawDocumentView → LawNodeList
  → ArticleLinkContext.lawByLawNumber → detectCrossLawSpan
```

同じ結果が既に入っていれば新しいオブジェクトを作らない既存の判定は、`lawId` と `title` の両方を比較する形に変える。参照比較にすると毎回新しいオブジェクトになり、再描画の輪に戻る。

### 3. 正式名称で境界を決める（`src/core/viewer/cross-law-span.ts`）

`readLawNumberParenthesis` が正式名称も返すようにし、`detectCrossLawSpan` で使う。

```ts
// 法令番号から引いた正式名称が括弧の直前にそのまま置かれていれば、境界はそこで厳密に決まる。
const readTitledLawName = (
  text: string,
  nameEnd: number,
  minIndex: number,
  title: string | undefined,
): number | undefined => {
  if (title === undefined) {
    return undefined;
  }

  const start = nameEnd - title.length;

  // 直前に確定したセグメントを越えて遡らない。
  if (start < minIndex) {
    return undefined;
  }

  return text.slice(start, nameEnd) === title ? start : undefined;
};
```

開始位置の優先順位を次のようにする。

1. 正式名称の一致（法令番号が決めるので最も確か）
2. 辞書の最長一致（`readDictionaryLawName`）
3. 左スキャン（`readFreeLawName`）

`readDictionaryLawName` と `resolveLawId` の役割は変えない。辞書一致による lawId と法令番号による lawId が食い違うときに宛先を伏せる既存の判定はそのまま残す。

### 4. 漢字ガードを法令番号の無い参照に限定する

現在のガードは、法令名の直前が漢字なら `旧民法` `新会社法` のような別法令を疑って宛先を伏せる。

境界を正式名称で決めると、このガードが**新たに 119 件**に掛かってリンクを失う。

```
附則第九条中農業協同組合法（昭和二十二年法律第百三十二号）第十一条
              ↑ 境界が正確になると直前が「中」= 漢字 → ガード発動
```

法令番号が併記されている参照では、宛先は名称ではなく番号が決める。`旧民法（明治二十九年法律第八十九号）` は番号のとおり現行の民法を指し、`明治二十三年法律第二十八号` を伴えば別の法令として引ける。名称の接頭辞を疑う理由が無いため、ガードは法令番号を伴わない参照（辞書一致の経路）に限定する。

### 5. 期待する効果

測定した 1,033 件（正解が引ける参照）のうち、飲み込み 197 件と切りすぎ 42 件の計 239 件（23%）で境界が正確になる。残る 29 件（3%）は本文が書かれた当時の名称と現在の正式名称が違うもので、従来の左スキャンのままになる。

## エラーとオフライン

正式名称が引けない、一致しない、カタログを読めない、いずれの場合も従来の左スキャンへ落ちる。下線が長くなることはあるが、リンク先は法令番号が決めるため誤リンクにはならない。

## テスト

- `law-number-resolver.test.ts`
  - e-Gov から解決したとき正式名称を載せる
  - カタログのキャッシュから解決したとき正式名称を載せる
  - 政令の導出でカタログに正式名称があれば載せ、無ければ lawId だけを返す
  - 政令の導出でネットワークに出ない（既存のテストを新しい戻り値へ追随させる）
- `cross-law-span.test.ts`
  - 正式名称が括弧の直前にあれば、先行語句を飲み込まずそこを開始位置にする
  - 正式名称に `、` を含む法令で、切りすぎずに開始位置を決める
  - 正式名称が `minIndex` を越える位置から始まる場合は使わず、左スキャンへ落ちる
  - 正式名称が本文の表記と違う（改称）場合は左スキャンへ落ちる
  - 法令番号を伴う参照では、直前が漢字でも宛先を伏せない
  - 法令番号を伴わない辞書一致の参照では、従来どおり直前が漢字なら宛先を伏せる
- `use-cross-law-numbers.test.ts`: 対応表が lawId と正式名称の両方を載せる
- `LawNodeList.test.tsx`: 正式名称を渡すと下線の範囲が法令名から始まる

## v1 に含めない

- 表記ゆれの正規化による名称一致
- 改称された法令の旧名称の辞書
- 法令番号を伴わない辞書外の法令名（[#279](https://github.com/SlashNephy/surasura-roppou/issues/279) で扱う略称定義とは別問題）
