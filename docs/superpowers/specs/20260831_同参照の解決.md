# 「同法」「同条」「同項」「同号」を先行詞から解決する（設計）

- Issue: [#219](https://github.com/SlashNephy/surasura-roppou/issues/219)
- 前提: [#200](https://github.com/SlashNephy/surasura-roppou/issues/200) で他法令への参照をリンク化済み

## 背景

`同法` `同条` `同項` `同号` は本文のリンク化パターンに含まれておらず、一切リンクにならない。`同条第4項` は `第4項` の部分だけがマッチし、直前 1 文字の `条` がガードに掛かって抑止される。

したがって本件は純粋な追加であり、既存の誤リンクを増やす方向の変更ではない。

## 実データから得た要点

原子力災害対策特別措置法の本文から `同[法条項号]` の出現を採取した（2026-08-31）。

### レベルごとに独立して追う必要がある

```text
規制法第13条第1項の規定に基づく加工の事業の許可（規制法第76条の規定により
読み替えて適用される同項の規定による国に対する承認を含む。）
```

`同項` は直前の `第76条` ではなく、その前の `第13条第1項` を指す。`第76条` は項を名指ししていないため先行詞にならない。「直前の参照」を 1 つ持つだけでは解けない。

### 解決できない先行詞のほうが多い

```text
原子力損害の賠償に関する法律の規定に基づき同法第2条第2項に規定する
```

先行詞は法令番号を伴わない辞書外の法令名で、位置表現も伴わないため現在のスパン検出に掛からない。この種は無リンクのままにする。

### 解決できて価値がある形

```text
第15条第2項の規定による原子力緊急事態宣言があった時から同条第4項の規定による…
前条第1項の原子力事業者防災業務計画に従い、同項に規定する…
```

いずれも自法令内で、先行詞が既にリンクになっている。

## 決定事項

| 論点                 | 決定                                                         |
| -------------------- | ------------------------------------------------------------ |
| 先行詞を遡る範囲     | 同じ文の中だけ。句点（。）でリセットする                     |
| 先行詞が他法令のとき | lawId が確定していればリンクする。確定していなければ無リンク |
| `同法` の先行詞      | 位置表現を伴う参照からだけ拾う。法令名単独の言及は追わない   |
| パーサーの契約       | 変えない。`同X` の判定は `reference-links` 側で原文から行う  |

## 設計

### 1. 本文パターンの拡張（`src/core/jump/reference-pattern.ts`）

`同法` `同条` `同項` `同号` を先頭トークンとして追加し、後続の条・項・号と 1 スパンにまとめる。

```text
同条第4項          → 1 スパン
同法第2条第1項     → 1 スパン
同項第3号          → 1 スパン
```

OCR 検出（`referencePositionPatternSource`）には含めない。`同X` は文脈が無いと解決できず、OCR の候補解決は 1 参照だけを見るため。

`同法` 単独（位置表現を伴わない）はリンクしない。着地先が法令のトップページになり、条を読んでいる文脈では動きの薄いリンクになるため。

### 2. パーサーの契約は変えない

`parseReference` は `ParsedReference` を返し、OCR 検出（`reference-detector`）と候補解決（`candidate-resolver`）も同じ型を使う。`article: "same"` のような値を足すと、それらの経路すべてが `"same"` を解釈しなければならなくなる。

代わりに `reference-links` 側で、マッチした原文が `同[法条項号]` で始まるかを見る。`同X` を剥がした残りは既存の `parseReference` に渡して、後続の条・項・号を読む。

### 3. 先行詞の追跡（`src/core/viewer/reference-links.ts`）

レベルごとに独立して持つ。

| 状態        | 更新するとき       | 保持する内容                          |
| ----------- | ------------------ | ------------------------------------- |
| `law`       | 法令名を伴う参照   | lawId（解決できなければ「解決不能」） |
| `article`   | 条を名指しする参照 | lawId + 条番号                        |
| `paragraph` | 項を名指しする参照 | lawId + 条番号 + 項番号               |
| `item`      | 号を名指しする参照 | lawId + 条番号 + 項番号 + 号番号      |

マーカーとレベルの対応は表で持つ。`同表` `同編` `同章` のような追加は、この表への追加とパターンの選択肢追加だけで済むようにする。

**リンクにならなかった参照も記録する。** 記録しないと、辞書外の法令を指す `同項` が、同じ文の前方にある自法令の項へ誤って結び付く。記録して「解決不能」と印を付けておけば、`同項` も無リンクになる。

句点（。）でリセットする。既存の `articleScopeEndIndex` と同じ振る舞いで、走査ループの同じ箇所で行う。

### 4. 解決

`同法` は `law`、`同条` は `article`、`同項` は `paragraph`、`同号` は `item` を基準にする。基準が無い、または解決不能なら無リンク。

先行詞が持つ lawId が現在の法令と同じ（または lawId を持たない）なら、既存の自法令内解決と同じ検証を通す（条・項が実在するか）。他法令なら、既存の他法令リンクと同じく検証しない。

`同条第4項` のように後続の位置指定があれば、先行詞の条番号と組み合わせる。`同項第3号` なら先行詞の条・項に号を足す。

### 5. 見た目

リンク範囲はスパン全体（`同条第4項`）。条見出し `〈 〉` の注入は既存の規則（他法令 target には付けない、現在の条自身には付けない）をそのまま使う。

## テスト

- `reference-pattern.test.ts`: `同条第4項` `同法第2条第1項` `同項第3号` が 1 スパンでマッチする。OCR 用パターンには含まれない
- `reference-links.test.ts`:
  - `第15条第2項の規定…同条第4項` → 同条第4項 が第15条へリンクする
  - `前条第1項…同項` → 前項ではなく前条の第1項へリンクする
  - `商法第15条第1項…同項` → 商法第15条へリンクする
  - `規制法第13条第1項…規制法第76条…同項` → 同項は無リンク（先行詞が解決不能）。自法令の項へ落ちない
  - `同項` の先行詞が無い（文頭）→ 無リンク
  - 句点をまたぐと先行詞が切れる
  - `同法` 単独は無リンク

## v1 に含めない

- 法令名単独の言及（位置表現を伴わない）を `同法` の先行詞にすること
- 文をまたぐ先行詞
- `同表` `同編` `同章` `同節` などのマーカー。追加できる形にはしておく
