# 基準日時点に版がない法令の現行法フォールバック設計

関連: [Issue #225](https://github.com/SlashNephy/surasura-roppou/issues/225) / [PR #227](https://github.com/SlashNephy/surasura-roppou/pull/227)（前段）
先行 ADR: [2026-07-09-egov-asof-server-side-resolution.md](../../adr/2026-07-09-egov-asof-server-side-resolution.md)

基準日を設定していると、基準日より後に施行された法令が本文を開けない。PR #227 で原因が分かる文言にはしたが、読めないことに変わりはない。本設計では読めるようにする。

## 背景

e-Gov API v2 の `law_data` は、`asof` 時点にその法令の版が存在しないとき HTTP 404（`code: 404004`）を返す。先行 ADR は `asof` を「施行日 ≤ asof の最新版」を返すサーバー側の版解決として採用したが、**該当する版が 1 つも無い場合**の扱いは定めていなかった。

新しく制定された法令はこれに該当する。本 issue の契機となった「国旗の損壊等の処罰に関する法律」（令和 8 年法律第 69 号・施行 2026-08-13）は、基準日 2026-04-01 では 404 になる。

一方でカタログ検索は `asof` を渡さないため現行法がヒットする。「検索には出るのに開けない」という非対称が利用者から見た症状である。

## 目的の再定義

基準日は**既定の版を選ぶ機能**であり、出題範囲のフィルタではない。

- 試験実施団体の出題基準は「試験年 4 月 1 日現在施行の法令」だが、実際には基準日後に施行された法令が問われることがある。社会的関心の高い新法ほどその可能性は上がる。
- 基準日はあくまで「特に指定がなければこの時点の条文を見せてほしい」という既定値である。既定値が存在しないことは、その法令を読めなくする理由にならない。

したがって、**基準日時点に版がない法令は現行法として表示し、基準日の対象外であることを表示に残す**。

版が存在する法令については従来どおり基準日時点の版を返す。改正によって基準日時点の古い版が返るケースは、基準日の本来の動作なので変更しない。

## 表示方針

自動で現行法を表示し、警告色のバナーは出さない。読めることが正常系であり、注意を促す事象ではないためである。

代わりにヘッダの書誌情報の基準日ラベルを変える。

| 状況       | ラベル                                                             |
| ---------- | ------------------------------------------------------------------ |
| 基準日あり | `基準日 2026/04/01 ・ 施行日 2026/08/13 版`                        |
| 対象外     | `基準日 2026/04/01（対象外・現行法を表示）・ 施行日 2026/08/13 版` |
| 基準日なし | `基準日 未設定（現行法）・ 施行日 2026/08/13 版`                   |

施行日は既に併記されているので、「基準日より後に施行された」という事実は 2 つを並べれば読み取れる。文言で施行日を繰り返さない。

## ローダーの変更

`loadLawViewerDocument`（[src/app/law-viewer-loader.ts](../../../src/app/law-viewer-loader.ts)）で、PR #227 が切り分けのために行っている現行法の再取得を、そのままフォールバック取得に格上げする。取得結果を捨てずに表示へ渡すだけなので、リクエスト数は PR #227 から増えない。

基準日あり・404 のときの分岐:

| 再取得の結果   | 返す状態                                           |
| -------------- | -------------------------------------------------- |
| 成功           | `ready`（現行法の本文）＋ `baseDateFallback: true` |
| 404            | `error`「法令が見つかりません。」                  |
| それ以外の失敗 | `error`「法令を取得できませんでした。…」           |

保存済み本文へのフォールバックは本設計の対象外とする（別タスク）。

## 状態と型

`LawViewerDocument` に `baseDateFallback?: boolean` を追加する。`requestedAsOf` は既存フィールドをそのまま使い、フォールバック時も**要求した基準日**を保持する（表示に必要なため）。

`baseDateFallback` が真になるのは「基準日を指定したが、その時点に版がなく現行法を取得した」場合だけである。基準日未設定時は付与しない。

## 保存時の版の扱い

[src/app/law-viewer-page.tsx](../../../src/app/law-viewer-page.tsx) は保存メタの `isCurrent` を 2 か所で算出している。

- 自動保存: `isCurrent: asOf === undefined`
- ダウンロード（pin）: `isCurrent: state === baseState && baseState.requestedAsOf === undefined`

フォールバック時に取得しているのは現行法なので、どちらも「基準日未指定、**または**フォールバック表示」を現行版とみなすよう改める。判断が 2 か所に散らないよう、`LawViewerDocument` を受け取る共有ヘルパーに寄せる。

これを怠ると、保存リストで現行法が「基準日 2026/04/01 時点の版」として記録され、後の再取得判定や履歴版のエビクション（[2026-08-17-storage-eviction-design.md](2026-08-17-storage-eviction-design.md)）が誤った前提で動く。pin 側は過去に同種のバグ（過去版が現行版スロットを奪う）があり回帰テストが残っているため、両方を同時に直す。

## 波及

- 復習カード（[src/app/study-review-page.tsx](../../../src/app/study-review-page.tsx)）は同じローダーを使うため、基準日後に施行された法令のカードが自動的に開けるようになる。追加変更は不要。
- 設定画面の基準日 UI は変更しない。基準日の意味づけ（既定の版）は変わっておらず、新たなトグルも設けない。

## テスト

- ローダー: 上表の 3 分岐。フォールバック成功時に `baseDateFallback: true` と `requestedAsOf` が両方載ることを確認する。
- ビューア: `baseDateFallback: true` の状態で基準日ラベルに「対象外」が出ること。
- 保存: フォールバック時の保存メタが `isCurrent: true` になること（自動保存・pin の両方）。

## 決定記録

先行 ADR の前提（`asof` を渡すだけでよい）に「該当版がない場合は現行法へ落とす」という例外を加えるため、ADR を 1 本追加する。
