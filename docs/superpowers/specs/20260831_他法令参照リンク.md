# 条文中の他法令への参照をリンク化する（設計）

- Issue: [#200](https://github.com/SlashNephy/surasura-roppou/issues/200), [#217](https://github.com/SlashNephy/surasura-roppou/issues/217)
- 前提: [#192](https://github.com/SlashNephy/surasura-roppou/issues/192) で同一法令内の条・項参照をリンク化済み

## 背景

`segmentReferenceLinks` は位置表現（`第15条第2項`）だけを正規表現で拾い、法令名は 2 段のガードで**抑止**している。

1. `hasPrecedingLawName`: alias 辞書によるマッチ直前の後方スキャン
2. `hasPrecedingGuardChar`: マッチ直前 1 文字が `法` `令` `則` `例` `条` `編` `章`

この設計には 2 つの問題がある。

- 他法令へのリンクが一切張れない
- 法令名と位置表現の間に法令番号の括弧書きが挟まると、どちらのガードも効かず**自法令の同じ条番号へ短絡する**（#217）

## 決定事項

| 論点                 | 決定                                                                                     |
| -------------------- | ---------------------------------------------------------------------------------------- |
| 信用する法令名の表記 | 正式名称（`matchKind === "official"`）のみリンク化する。略称は抑止シグナルとしてのみ使う |
| 辞書外の法令         | 法令番号から lawId を導出できる場合はリンク化する                                        |
| 解決方式             | 同期・純粋関数のみ。e-Gov への問い合わせは v1 に含めない                                 |
| 着地の粒度           | 項・号をクエリパラメータに載せる                                                         |
| 「同法第3条」        | v1 では無リンク                                                                          |
| リンク範囲           | 法令名から位置表現末尾までのスパン全体                                                   |

## e-Gov lawId の導出可否（実 API で検証、2026-08-31）

lawId は `{元号コード1桁}{年2桁}{種別コード2桁}{8桁}` の形をとる。元号コードは明治 1、大正 2、昭和 3、平成 4、令和 5。元年は `01`。

`law_num_era` / `law_num_year` / `law_num_type` / `law_num_num` で全件を走査し、法令番号からの導出結果と実 lawId を突き合わせた（2420 件）。

| 種別        | 末尾 10 桁の先頭 2 桁 | 件数        | 導出     |
| ----------- | --------------------- | ----------- | -------- |
| 政令 (`CO`) | `00`                  | 1244 / 1244 | **可能** |
| 法律 (`AC`) | `00`（閣法）          | 914 (78%)   |          |
| 法律 (`AC`) | `10`（衆法）          | 224 (19%)   |          |
| 法律 (`AC`) | `01`（参法）          | 38 (3%)     |          |

法律の lawId には**提出区分**が埋まっており、法令番号からは決定できない。外した lawId は e-Gov が `404 / 404004` を返すため、22% の法律参照が壊れたリンクになる。したがって**導出は政令に限る**。

府令・省令の種別コードは省庁コードを含む（`M10000001` = 閣令、`M10000040` = 大蔵省令）ため、そもそも導出できない。

法律を法令番号で解決するには `GET /api/2/laws?law_num_era=Heisei&law_num_year=11&law_num_type=Act&law_num_num=156` が一意に引ける（`total_count: 1`）。これは非同期になるため後続 issue とする。

## 設計

### 1. 法令番号のパースと lawId 導出（新規 `src/core/jump/law-number.ts`）

```ts
export type LawNumberEra = "Meiji" | "Taisho" | "Showa" | "Heisei" | "Reiwa";

export interface ParsedLawNumber {
  era: LawNumberEra;
  year: number; // 元年は 1
  type: string; // 原文の種別語（法律・政令・省令 …）
  number: number;
}

export const lawNumberPatternSource: string;
export const parseLawNumber: (text: string) => ParsedLawNumber | undefined;
export const deriveLawIdFromLawNumber: (parsed: ParsedLawNumber) => string | undefined;
```

- 数字は漢数字・算用数字・全角数字のいずれも受ける。readable 表示は法令番号のうち**法律のみ**を算用数字へ変換する（`transformLawNumbers`）ため、同じ文書でも法律は算用数字・政令は漢数字で現れる
- 括弧は `[（(]` `[）)]` の両方を受ける。readable 表示は `transformParentheses` で全角へ揃えるが、原文表示では半角がありうる
- `deriveLawIdFromLawNumber` は種別が政令のときだけ `${eraCode}${年2桁}CO${号10桁}` を返す。法律・省令・その他は `undefined`

**検出は導出より広く取る**。省令・府令・太政官布告の括弧書きも「法令番号らしきもの」として `parseLawNumber` は成功させる。lawId を出せないだけで、スパンとしては認識させて自法令への短絡を止める必要があるため。

### 2. 法令名スパンの検出（`src/core/viewer/reference-links.ts`）

位置表現のマッチごとに、左方向を解析して 1 つのスパンにまとめる。

```
［法令名］［（法令番号）］［位置表現］
```

1. マッチ直前に括弧があり、中身が法令番号としてパースできれば剥がす
2. その手前（括弧が無ければマッチ直前）から法令名を取る
   - **辞書経路**: 既存の後方スキャンを流用し、最長一致を取る
   - **法令番号経路**: 括弧がある場合は辞書に無くてよい。括弧の直前から左へ、句読点（`、` `。`）・括弧・引用符・空白・**直前セグメントの末尾**のいずれかに当たるまで走査する。直前セグメントで止める clamp は、「民法第95条及び不正競争防止法（…）第4条」で前のリンクを跨がないために必要。先頭に残る接続語（`及び` `並びに` `又は` `若しくは` `、` `・`）は `coordinationGapPattern` と同じ語彙で剥がす
3. 法令名の直前 1 文字が漢字なら不採用にする。「**旧**民法第90条」「**新**会社法第2条」が現行法へ飛ぶのを防ぐ

スパンは 3 分類になる。

| 分類               | 条件                                | 挙動                                             |
| ------------------ | ----------------------------------- | ------------------------------------------------ |
| `self`             | 法令名も法令番号も無い              | 現行どおり自法令内で解決する                     |
| `cross-resolved`   | lawId が確定                        | 他法令へのリンクにする                           |
| `cross-unresolved` | 法令名らしきものはあるが lawId 不明 | 無リンク。ただし `articleScopeEndIndex` は立てる |

`cross-unresolved` が #217 の修正にあたる。「原子力災害対策特別措置法（平成11年法律第156号）第2条」は辞書外だが、括弧書きを手掛かりにスパンとして認識され、自法令の第2条へ短絡しなくなる。

`articleScopeEndIndex` は `cross-resolved` でも立てる。そうしないと「商法第798条第2項及び第3項」の後半の裸の項参照が、自法令の条の項へ誤解決する。現状は抑止経路でしか立てていない。

### 3. lawId の決定

1. 法令番号から導出できれば、それを採る
2. 導出できなければ、辞書の正式名称一致（`matchKind === "official"`）を採る
3. 両方あって食い違うときは無リンクにする

略称一致（`matchKind === "alias"`）は**リンク化しない**。条文の原文は正式名称と法令番号で引用し、`民` `刑訴` のような学習者略称は現れないため、本文では誤検出の面にしかならない。ただし抑止シグナルとしては残す。「民訴第三条」は直前が `訴` でガード 2 をすり抜けるため、alias スキャンが無いと自法令の第3条へ短絡する。

### 4. 型と描画

- `ArticleLinkTarget` に `lawId?` と `itemNumber?` を足す。`lawId` があるものが他法令リンク
- 他法令 target では項・号の存在を検証しない。別法令のノードを持たないため検証しようがなく、`buildLawArticleUrl` にそのまま渡す。着地先ページの「指定された条文が見つかりません」を最後の砦にする
- `buildCaption` は他法令 target には見出しを付けない。条番号が偶然一致したときに自法令の見出しを貼ってしまうため
- `LawNodeList` の `ReferenceSegment` は `target.lawId` があれば `onSelectArticle` を使わず通常遷移にする。リンク文字列はスパン全体（法令名〜位置表現）
- 編・章だけを名指しする他法令参照（「会社法第2編第2章」）は v1 では無リンク。着地先アンカーが別法令のページにあり、ページ内リンクでは表現できない

### 5. 既存ガードの整理

`hasPrecedingLawName` はスパン検出器に統合する。同じ後方スキャンを、抑止の真偽値ではなく「official 一致 → リンク、alias 一致のみ → 抑止」の分類に使う。ガードを重ねるのではなく、1 つの機構にまとめる。

`hasPrecedingGuardChar` は残す。法令番号の括弧書きが無い辞書外の法令名（「不正競争防止法第2条」）と「同条」を止める役目は、スパン検出では代替できない。

## テスト

- `law-number.test.ts`: 漢数字・算用数字・全角数字、元年、全角括弧と半角括弧、政令・法律・省令・太政官布告、不正な年（0・3 桁）
- `reference-links.test.ts`: #217 の実文、`民法第709条`、`旧民法第90条`、政令の法令番号、辞書外かつ括弧なし、列挙スコープの継続、`同法第3条`
- `LawNodeList.test.tsx`: 他法令リンクの href が `/laws/{lawId}/articles/{n}?paragraph=1` になる DOM 契約

## v1 に含めない（後続 issue）

- 「同法第3条」。直前に解決した lawId を文スコープで保持する必要があり、括弧内引用をまたぐ射程と文境界の切り方が別議論になる
- 法律の法令番号による解決（`law_num_*` の 4 パラメータで一意に引けるが非同期）
- 括弧書きが無い辞書外の法令名（`title` 検索の完全一致＋単一ヒットで解決できるが非同期）
- 編・章だけを名指しする他法令参照

## 既知の制限

「〜に規定する原子力災害対策特別措置法（…）」のように、法令名の左境界が助詞まで伸びてリンクの下線が長くなることがある。lawId は法令番号から決まるので**リンク先は正しく**、下線の範囲だけの問題。法令名の一覧を持たない限り境界を厳密に決められず、日本語の法令名は平仮名で始まるものもある（たばこ事業法、あん摩マツサージ指圧師、はり師、きゆう師等に関する法律）ため、先頭の平仮名を一律に削ることもできない。

枝番の条番号（`第876条の9`）への他法令リンクは張らない。アプリ正準表記が e-Gov の Num 由来で `876_9`、パーサーの出力が `876-9` と割れており、他法令のノードを持たない以上どちらで着地するか確かめられないため。

他法令へのリンクはブラウザの通常遷移になり、SPA 内遷移にはならない。`onSelectArticle` は同一法令内の条移動のためのコールバックで、別法令のページへは使えない。ルーターの `Link` を使うにはテストでルーターコンテキストが要るため、v1 では素の `<a href>` に倒す。

左スキャンの下限（`minIndex`）には「直前に確定したセグメントの終端」（`lastIndex`）を使う。直前のマッチの終端は使えない。法令番号の括弧書きの中にある「第二十一号」自体が位置表現としてマッチするため、直前のマッチ終端は括弧の内側になり、括弧の検出そのものが壊れる。

そのままだと、リンクにならなかった参照を後続の他法令リンクが飲み込む（「不正競争防止法第15条及び労働基準法施行令（…）第1条」の全体が 1 リンクになる）。これを防ぐため、左スキャンの境界文字に位置表現の末尾になる `条` `項` `号` `編` `章` と `第` を含めている。失敗の方向は安全側で、法令名に `条`（…条約）や `章`（…憲章）が含まれるとスキャンが手前で止まり下線が短くなるだけで、リンク先は法令番号から決まるため正しいままになる。
