# 保存容量の上限とエビクション（PR 3）設計

親設計: [2026-08-16-auto-offline-save-design.md](2026-08-16-auto-offline-save-design.md)
前段: [2026-08-16-pinned-and-auto-save-design.md](2026-08-16-pinned-and-auto-save-design.md)（PR 2）

PR 2 で法令を開くたびに自動保存するようにした結果、保存領域は増える一方になった。本 PR で上限を設け、超えた分を削除する。あわせて `navigator.storage.persist()` を要求し、使用量を可視化し、手動削除の導線を戻す。

## 目的の再定義

親設計は本 PR を「件数上限と LRU エビクション」と位置づけていたが、ブラウザの実際の挙動を確認した結果、重心を変える。

ブラウザのオリジンあたりの上限は Chrome / Safari でディスク全体の約 60%、Firefox は best-effort でディスクの 10% か 10 GiB の小さい方である。法令 1 件は e-Gov の生 JSON で 385 KB（刑法）から 2.9 MB（会社法）なので、容量そのものは制約にならない。

制約になるのは消され方である。

- **逼迫時の LRU 退避**: ブラウザは容量が逼迫すると使用頻度の低いオリジンから削除する。削除は**オリジン単位でまとめて**行われ、保存法令だけでなくブックマーク・学習カード・注釈・OCR セッションも同時に失われる。
- **WebKit の 7 日ルール**: Safari で 7 日間サイトへの操作がないと、IndexedDB を含む script-writable storage がまるごと削除される。試験前に集中して使い、間が空くという本アプリの使われ方と正面から衝突する。ホーム画面に追加した PWA の第一パーティドメインは対象外になる。

したがって本 PR の目的は「ブラウザの上限に当たらないようにする」ことではない。**再取得できないユーザー資産（学習カード、注釈、ブックマーク、コレクション）を守ること**である。法令本文は e-Gov から再取得できるキャッシュなので、これを自ら間引いてオリジン全体を軽く保ち、退避の標的になりにくくする。`persist()` の要求は付随機能ではなく、この目的に対する主要な手段である。

## 用語

UI の語彙を「ダウンロード」に改める。PR 2 の「ピン留め」は仕組みの名前であり、押さなかったときに何が起きるかを語らない。自動削除が入る本 PR では、この語は意味を伝えられない。

| 概念                 | UI 表記              | 内部識別子                           |
| -------------------- | -------------------- | ------------------------------------ |
| 法令単位の削除保護   | ダウンロード（済み） | `pinnedLaws` / `isLawPinned` / `pin` |
| ブックマークの版固定 | 固定                 | `bookmark.target.pinned`             |

内部識別子は変更しない。表示のみの変更に留めることで、ストア名の変更に伴う移行を増やさずに済む。副次的に、PR 2 の計画書が警告していた `pinned` の二義性が UI から解消される。

**ユーザーから見た意味**: 「ダウンロード」は端末に確保しておく操作を指す。実際には開いた時点で自動保存済みだが、その本文は容量が逼迫すれば削除されうる。ダウンロード指定した法令だけが削除されない。Netflix や Spotify がキャッシュの有無ではなくダウンロード指定の有無を表示するのと同じ構造である。

## データモデル

`SavedLawRecord` に `byteSize?: number` を足す。DB バージョンは 5 のまま上げない。IndexedDB はレコード単位でスキーマを持たず、索引も追加しないため、移行は不要である。

保存時に `new Blob([JSON.stringify(nodes)]).size` で 1 回だけ測って記録する。エビクションのたびに本文を読み直す必要がなくなり、`by-updated-at` 索引の走査だけで合計を出せる。

**PR 2 以前に保存されたレコード**: `byteSize` を持たない。合計には含めず、表示上も容量を出さない。自動保存はその法令を開くたびに走るので、通常の利用で順次埋まる。加えてエビクションのパスで、`byteSize` を持たないレコードに出会ったら実測して書き戻す。バックグラウンドで走るため、本文の読み込みが必要でも閲覧を妨げない。

versionchange トランザクション内で一括計算する案は採らない。全法令の全ノードを読む必要があり、DB を開く経路が重くなるうえ、失敗すれば DB そのものが開けなくなる。

## エビクションの規則

**ダウンロード指定が守るのは現行版だけである。**

ユーザーがダウンロードで表明した意図は「この法令をオフラインで読めるようにしておきたい」であり、「基準日を変えて覗いた過去版を全部取っておきたい」ではない。したがって履歴版は指定の有無を問わず削除対象とする。

削除は 2 段階で行う。

1. **履歴版を消す**: `isCurrent: 0` のレコードを `updatedAt` 昇順に削除する。ダウンロード指定の有無を問わない。
2. **法令を丸ごと消す**: 第 1 段で上限を下回らなければ、ダウンロード指定のない法令を `updatedAt` 昇順に、全版・ノード・`laws` メタ・`pinnedLaws` レコード・検索索引ごと削除する。

第 1 段が非現行版しか削除しないため、**「現行版だけ消えて履歴版が残る」状態をエビクションは作らない**。PR 2 から申し送った「現行版を削除したときにどの版を昇格させるか」という問題は、昇格ロジックを書かずに解消する。`deleteLawRevision` の既存の振る舞い（昇格しない）は変更しない。

**置き場所**: `SavedLawUseCase` に置く。法令を丸ごと削除する際に `indexer.removeLaw` を呼ぶ必要があり、これはリポジトリが知らない依存である。PR 2 から申し送った「`deleteLawRevision` の `searchPostings` 後始末」もここで解決する。検索索引は現行版の本文しか持たないため、後始末が要るのは法令単位の削除だけである。

**走らせるタイミング**: 自動保存が成功した直後のみ。合計が増えるのはこの瞬間だけであり、起動時や定期実行の理由がない。閲覧を妨げないよう `await` せず、失敗は握りつぶす（PR 2 の自動保存と同じ扱い）。

**上限値**: 既定 50 MB。設定で 25 / 50 / 100 MB から選ぶ。会社法が生 JSON で 2.9 MB なので、50 MB はおおむね 30〜50 法令にあたり、六法と主要な特別法を手元に置くには足りる。

## ブラウザの quota との関係

上限（我々の都合）とブラウザの quota（環境の都合）は別物である。ディスクが逼迫していれば、50 MB の上限に余裕があっても `QuotaExceededError` は飛ぶ。

このとき何もしないと保存が失敗し続けるため、`saveLawDocument` が `QuotaExceededError` で失敗したらエビクションを 1 回走らせ、保存を 1 度だけ再試行する。再試行も失敗したら諦める。自動保存の失敗はバナーを出さないという PR 2 の方針は維持する。

## `persist()` の要求

`navigator.storage.persist()` は呼ばない限り granted にならない。Chrome と Safari はヒューリスティックで即答し、Firefox はプロンプトを出す。

**初回のダウンロード指定時に一度だけ要求する。** ダウンロードは「これを残しておきたい」という最も明確な意思表示であり、Firefox のプロンプトが出てもユーザーが文脈を理解できる唯一の瞬間である。設定画面のボタンだけにすると、そこまで辿り着かないユーザーが永久に保護されない。

設定画面には状態表示と再要求ボタンを置く。拒否されてもバナーは出さない。ユーザーが要求していない保護の失敗で閲覧を止める理由がない。

**Safari の 7 日ルール**: `persist()` が効くかは非公式なので当てにしない。確実な回避策はホーム画面への追加なので、保護が有効でないときの説明文にその旨を書く。ブラウザ判定で出し分けると壊れやすいため、判定せず一般的な案内にする。

## 使用量の可視化

上限を設けても確認手段がなければ「いつか勝手に消える」としか感じられない。

**保存リストの各行に容量を出す。** 現在表示している「4,283 ノード」を容量表示に差し替える。ノード数は判断材料にならない。

表示する値は**その法令の全版の合計**とする。現行版だけの数字にすると、基準日を変えて何度か覗いた法令が実際より小さく見え、履歴版が削除されたときに「消したのに減らない」という不可解な挙動になる。

`listSavedLaws` は既に `savedLaws` を全走査して非現行版を読み飛ばしている。同じ走査の中で `lawId` ごとに `byteSize` を積むだけなので、索引もクエリも増えない。

**保存リストの先頭に合計と上限を出す。** `28.4 MB / 50 MB` に加えてダウンロード済み分と最近開いた分の内訳を出す。エビクションの対象が後者だけなので、消える余地がこの内訳で読める。

**次に消えるものは既に並び順が表している。** PR 2 で「最近開いた法令」を `updatedAt` 降順にした理由がこれである。新しい UI は足さず、セクションの説明文で順序の意味を開示する。

**設定画面には `navigator.storage.estimate()` の値を出す。** 保存リストが「オフライン法令が上限のどれだけを使っているか」を示すのに対し、こちらはオリジン全体の使用量である。`persist()` の状態と並べることで、何を守っているのかが読める。

## UI の変更

**ビューアのレール**: ボタンをアイコンとラベルだけにする。未指定は下向き矢印と「ダウンロード」、指定済みは丸囲みチェックと「ダウンロード済み」を成功色で表示する。PR 2 の「ピン留め中」バッジは削除する。ボタン自身が状態を表すため重複する。

説明文はレールに置かない。押さなかった場合に何が起きるかは保存リスト側（使用量メーターとセクションの説明文）で示す。

**緑のチェックはダウンロード指定の状態だけに結びつける。** 自動保存の状態に結びつけると、法令を開いた瞬間にチェックが点き、ユーザーが押していないのに押されたように見える。実際には端末にある本文を未ダウンロードの見た目で出すことになるが、ユーザーが知る必要がある事実（指定していないものは削除されうる）とは一致している。

**保存リスト**: セクション見出しを「ピン留めした法令」から「ダウンロード済み」に改める。もう一方は「最近開いた法令」のまま据え置く。未ダウンロード行に状態表示は出さない。セクションが分かれていること自体が状態を示しており、行ごとの表示は冗長である。

**手動削除**: 各行に削除ボタンを置き、`SavedLawUseCase.remove(lawId)` で全版・ノード・ダウンロード指定・検索索引を削除する。ダウンロード指定の有無にかかわらず確認ダイアログを出す。対象によってインタラクションが変わると学習コストになる。

## エラー処理

| 経路                     | 扱い                                                        |
| ------------------------ | ----------------------------------------------------------- |
| エビクションの失敗       | 握りつぶす。ユーザーが要求した操作ではない                  |
| `QuotaExceededError`     | エビクション後に 1 度だけ再試行。失敗したら諦め、バナーなし |
| `persist()` の拒否・失敗 | バナーを出さない。設定画面に状態として表示                  |
| `estimate()` の失敗      | 設定画面の使用量欄を空にする。他の項目は表示を続ける        |
| 手動削除の失敗           | 明示操作なのでバナーを出す                                  |

## テスト方針

振る舞いとして検証する。

- 上限を超えたとき、履歴版が `updatedAt` 昇順に削除されること
- 第 1 段で下回らないとき、ダウンロード指定のない法令が丸ごと削除され、指定済みの法令の現行版は残ること
- 法令単位の削除で `pinnedLaws` と検索索引も消えること
- `QuotaExceededError` のあとエビクションを経て保存が成功すること
- `byteSize` を持たないレコードがエビクションのパスで埋まること
- 保存リストに法令ごとの容量と合計が表示されること
- 設定画面が `persist()` の状態を表示し、ボタンで要求できること

`navigator.storage` はモックする。`byteSize` の値そのものを期待値と突き合わせるテストは書かない。実装の写しになり tautological である。上限値などの定数を定数と比較するテストも書かない。

## 非スコープ

- **上限のカスタム数値入力**: プリセットのみ。任意の値を入れられても判断材料がない
- **ホーム画面追加の能動的な誘導**: 説明文に留める。インストール導線そのものは別課題
- **版単位の手動削除 UI**: 履歴版はエビクションに委ねる。ユーザーが版を意識する画面が存在しない
- **エビクションの取り消し**: 削除した本文は e-Gov から再取得できる
