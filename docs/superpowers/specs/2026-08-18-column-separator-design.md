# Column に分かれた本文の区切り表示

Issue: #221

## 背景

e-Gov 法令データでは、号や項の本文が複数の欄に分かれる場合、`Column` タグの兄弟として表される。
すらすら六法は `Column` の境目に区切りを入れずに連結するため、定義語と定義文、要件と効果がひと続きの文に見える。

- 行政手続法 第2条第4号: `不利益処分行政庁が、法令に基づき、…`
- 所得税法 第28条第3項: `前項に規定する収入金額が190万円以下である場合65万円`

実データでは `Column` は `ItemSentence` などの Sentence コンテナ直下に `Num=1,2` の兄弟として現れる。
`Column` は `LawNode` にはならないため、テキスト生成の内側で完結する問題である。

## 方針

`src/core/egov/lawText.ts` のテキスト生成で、隣り合う要素の境界のいずれかが `Column` であれば全角空白 U+3000 を挟む。

- `collectPlainText`: 既存の `plainTextBlockTags` による半角空白連結はそのまま。`Column` 境界だけ全角空白を優先する。
- `collectRawText`: 同じ規則を適用する。原文表示と条文コピー（`src/core/viewer/article-copy.ts` は `rawText` を使う）が表示と揃う。
- ビューア（`src/core/viewer/LawNodeList.tsx`）とドメインモデル（`LawNode`）は変更しない。

欄ごとに要素を分けた対応表レイアウトは採らない。テキスト列を前提とする既存処理（親テキストからの子テキスト剥がし、参照リンク分割、コピー、OCR 照合）へ広く手を入れることになり、Issue の不具合解消に対して変更が過大なため。必要になった時点で別 Issue とする。

## 波及

- 条文指紋 `computeArticleFingerprint` は `\s`（U+3000 を含む）を全除去するため、指紋は変わらない。保存済みアンカーはドリフトしない。
- 検索の `normalizeForSearch` は空白をスキップしつつ元テキストへの対応表を保つため、索引とヒット位置は変わらない。スニペットに区切りが現れるだけである。
- 既にオフライン保存済みの法令は、再取得するまで旧テキストのままとなる。指紋が変わらないため警告も出ない。

## テスト

- `src/core/egov/lawText.test.ts` に `Column` を含む号のケースを追加し、`plainText` と `rawText` の双方で欄が全角空白で区切られることを確かめる。
- 欄が 1 つだけの場合や `Column` を含まない本文で、余分な空白が入らないことを確かめる。
- preview ビルドを立て、playwright-cli で行政手続法第2条第4号と所得税法第28条第3項の before / after を撮る。
