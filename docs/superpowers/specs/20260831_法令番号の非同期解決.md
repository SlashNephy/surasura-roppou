# 法令番号から lawId を非同期に解決する（設計）

- Issue: [#268](https://github.com/SlashNephy/surasura-roppou/issues/268)
- 前提: [#200](https://github.com/SlashNephy/surasura-roppou/issues/200) で他法令への参照をリンク化済み

## 背景

他法令へのリンクは同期・純粋関数で完結させたため、宛先を決められる範囲が次に限られている。

- 法令番号からの導出（**政令のみ**）
- alias 辞書の正式名称一致（13 法令）

lawId は `{元号コード1桁}{年2桁}{種別コード2桁}{8桁}` の形をとるが、法律の lawId には**提出区分**（閣法 `00` / 衆法 `10` / 参法 `01`）が埋まっており、法令番号からは決まらない。したがって法律への参照は、法令番号が併記されていても無リンクのままになっている。

一方 e-Gov は `law_num_era` / `law_num_year` / `law_num_type` / `law_num_num` の 4 パラメータで**一意に引ける**（`total_count: 1`）。

```
GET /api/2/laws?law_num_era=Showa&law_num_year=32&law_num_type=Act&law_num_num=166
→ 332AC1000000166 核原料物質、核燃料物質及び原子炉の規制に関する法律
```

## 測定した前提（2026-08-31）

| 項目                       | 実測                            |
| -------------------------- | ------------------------------- |
| 1 法令あたりの固有法令番号 | 原災法 15 / 民法 40 / 会社法 63 |
| 1 件の解決コスト           | 2.3 KB / 0.85 秒                |
| 全法令カタログ             | 9,551 件・約 19 MB              |

全カタログの一括取得は現実的でない。年単位のバッチ（昭和32年の法律 = 31 件）も、参照される法令番号が年をまたいで分散するため節約が小さい。**法令番号 1 件につき 1 リクエスト**を、並列度を抑えて投げる。

## 決定事項

| 論点                                           | 決定                                                                                         |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 解決中の見た目                                 | 解決できたものから順にリンク化する。レイアウトは動かず下線が増えるだけ                       |
| 法令番号を伴わない辞書外の法令名               | v1 に含めない。`title` 検索は部分一致で同名の絞り込み設計が別途要る                          |
| 法令が定義した略称（`以下「規制法」という。`） | v1 に含めない。[#279](https://github.com/SlashNephy/surasura-roppou/issues/279) に切り出した |
| `segmentReferenceLinks` の契約                 | 純粋・同期のまま。非同期は前段に閉じ込め、解決結果を対応表として渡す                         |

## 設計

### 全体の流れ

```text
法令本文ロード
  ↓
useCrossLawNumbers フック
  本文を走査 → 法令番号を重複排除 → キャッシュ照会 → 不足分を e-Gov へ（並列度制限）
  ↓ 解決できたものから Map を更新（再描画でリンクが増える）
segmentReferenceLinks（純粋・同期）
  context.lawIdByLawNumber を参照
```

### 1. 法令番号のキー（`src/core/jump/law-number.ts`）

表記が漢数字と算用数字で割れるため、突き合わせは構造化したキーで行う。

```ts
export const lawNumberKey = (parsed: ParsedLawNumber): string =>
  `${parsed.era}/${String(parsed.year)}/${parsed.type}/${String(parsed.number)}`;
```

API が返す `law_num`（常に漢数字）も `parseLawNumber` を通して同じキーにする。

### 2. e-Gov の構造化クエリ（`src/core/egov/repository.ts`）

`LawListQuery` に 4 つのフィールドを足す。既存の `lawNumber`（`law_num` の完全一致）は残す。

```ts
export interface LawListQuery {
  // 既存のフィールドはそのまま
  lawNumberEra?: string; // Meiji / Taisho / Showa / Heisei / Reiwa
  lawNumberYear?: number;
  lawNumberType?: string; // Act / CabinetOrder / ...
  lawNumberNumber?: number;
}
```

種別語（`法律` `政令` …）から API の種別コード（`Act` `CabinetOrder` …）への対応表を `law-number.ts` に持つ。対応の無い種別（府令・省令・太政官布告など）は解決を試みない。

### 3. 解決器（新規 `src/core/jump/law-number-resolver.ts`）

```ts
export interface LawNumberResolver {
  // キャッシュ優先で lawId を返す。解決できなければ undefined。
  resolve(parsed: ParsedLawNumber, options?: { signal?: AbortSignal }): Promise<string | undefined>;
}

export const createLawNumberResolver: (dependencies: {
  lawRepository: LawRepository;
  indexRepository: SearchIndexRepository;
}) => LawNumberResolver;
```

- まず `deriveLawIdFromLawNumber`（政令）を試す。決まればネットワークに出ない
- 次に `indexRepository.listCatalog()` のキャッシュを引く。**スキーマ変更は不要**で、既存の `lawCatalog` ストア（`LawCatalogEntry` が `lawId` と `lawNumber` を持つ）をそのまま使う。検索経由で入ったエントリも効く
- 最後に e-Gov へ問い合わせ、`total_count === 1` のときだけ採る。結果は `upsertCatalogEntries` でキャッシュへ書く
- 失敗した法令番号は解決器の中で「解決できなかった」として覚え、同じセッション中は再試行しない

### 4. 走査フック（新規 `src/app/use-cross-law-numbers.ts`）

```ts
export const useCrossLawNumbers: (
  nodes: LawNode[],
  resolver: LawNumberResolver,
) => ReadonlyMap<string, string>;
```

- ノードの `plainText` から法令番号の括弧書きを走査し、`parseLawNumber` でパースして重複排除する
- 並列度 6 で解決し、解決できたものから Map を更新する（`setState` で逐次反映）
- `nodes` が変わったら中断して作り直す（`AbortController`）

### 5. リンク側（`src/core/viewer/cross-law-span.ts`）

`detectCrossLawSpan` に `lawIdByLawNumber` を渡し、`deriveLawIdFromLawNumber` が `undefined` を返したときにこの表を引く。表に無ければ従来どおり「他法令参照だが宛先不明」で無リンクにする。

`ArticleLinkContext` に `lawIdByLawNumber?: ReadonlyMap<string, string>` を足し、`LawNodeList` → `LawDocumentView` → `law-viewer-page` の順に通す。

## エラーとオフライン

取得の失敗、`total_count !== 1`、種別が対応表に無い、いずれの場合もリンクが出ないだけで誤リンクにはならない。オフラインではキャッシュ済みのものだけが効く。

`AbortError` は正常系として扱い、失敗として記録しない（法令を切り替えたときに走る）。

## テスト

- `law-number.test.ts`: `lawNumberKey` が漢数字と算用数字の両方の表記から同じキーを作る
- `law-number-resolver.test.ts`: 政令はネットワークに出ない / キャッシュに当たればネットワークに出ない / `total_count === 1` のときだけ採る / 複数ヒットは `undefined` / 一度失敗した法令番号を再試行しない / 解決結果をキャッシュへ書く
- `cross-law-span.test.ts`: 対応表にある法令番号を引く / 無ければ従来どおり無リンク
- `use-cross-law-numbers.test.ts`: 重複した法令番号を 1 回しか解決しない / 解決できたものから Map に載る / nodes が変わったら中断する
- `LawNodeList.test.tsx`: 対応表を渡すと辞書外の法律がリンクになる

## v1 に含めない

- 法令番号を伴わない辞書外の法令名（`title` 検索）
- 法令が定義した略称（[#279](https://github.com/SlashNephy/surasura-roppou/issues/279)）
- 失敗した法令番号のセッションをまたぐ記憶（毎回の起動で再試行する）
