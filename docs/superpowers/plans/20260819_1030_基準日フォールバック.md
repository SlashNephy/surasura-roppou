> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 基準日時点に版が存在しない法令を、現行法として表示できるようにする（対象外である旨は表示に残す）。

**Architecture:** `loadLawViewerDocument` が基準日付き 404 の切り分けのために既に投げている「基準日なしの再取得」の結果を、捨てずに表示へ渡す。状態に `baseDateFallback` を足し、ビューアの基準日ラベルと保存メタ（`isCurrent`）がそれを見る。

**Tech Stack:** TypeScript / React 19 / TanStack Router / Vitest + Testing Library / pnpm

設計: [docs/superpowers/specs/2026-08-19-base-date-fallback-design.md](../specs/2026-08-19-base-date-fallback-design.md)

- [ ] **Step 4: ローダーを書き換える**

`src/app/law-viewer-loader.ts` の 404 分岐（`probeCurrentLaw` を呼んでいる `switch`）を次に置き換える。`probeCurrentLaw` は取得した文書を返すよう変える。

```ts
    // 基準日時点で施行されていない法令は e-Gov が 404（404004）を返す。基準日は既定の版を
    // 選ぶ機能であり出題範囲の絞り込みではないため、版が無いときは現行法を表示する。
    if (asOf !== undefined) {
      const fallback = await fetchCurrentLaw(repository, lawId);

      switch (fallback.status) {
        case "fetched":
          return {
            status: "ready",
            law: fallback.document.law,
            revision: fallback.document.revision,
            nodes: fallback.document.nodes,
            isPinned,
            loadedFromStorage: false,
            requestedAsOf: asOf,
            baseDateFallback: true,
            savedAt: savedDocument?.savedAt,
          };
        case "not-found":
          break;
        // 取得できなかった以上「見つからない」と断定できない。取得失敗として扱う。
        case "failed":
          return {
            status: "error",
            message: "法令を取得できませんでした。ネットワーク接続を確認してください。",
          };
      }
    }

    return { status: "error", message: "法令が見つかりません。" };
  }
};

// 基準日抜きで取得できるなら現行法として表示する。404 なら法令 ID が存在しない。
// それ以外の失敗（通信断・5xx など）はどちらとも判定できない。
type CurrentLawFetchResult =
  | { status: "fetched"; document: LawDocument }
  | { status: "not-found" }
  | { status: "failed" };

const fetchCurrentLaw = async (
  repository: LawRepository,
  lawId: string,
): Promise<CurrentLawFetchResult> => {
  try {
    return { status: "fetched", document: await repository.getLaw(lawId, {}) };
  } catch (error) {
    return error instanceof EgovApiError && error.status === 404
      ? { status: "not-found" }
      : { status: "failed" };
  }
};
```

`LawDocument` 型の import を足す。

```ts

```

不要になった `formatIsoDateLabel` の import は削除する（この時点で参照が無くなる）。

- [ ] **Step 1: ADR を書く**

```markdown
# 基準日時点に版がない法令は現行法へフォールバックする

Date: 2026-08-19

## Status

Accepted

## Context

[2026-07-09 の ADR](2026-07-09-egov-asof-server-side-resolution.md) は `asof` を「施行日 ≤ asof の最新版」を返すサーバー側の版解決として採用したが、該当する版が 1 つも無い場合の扱いを定めていなかった。

基準日より後に制定・施行された法令はこれに該当し、e-Gov は HTTP 404（`code: 404004`）を返す。カタログ検索は `asof` を渡さないため現行法がヒットするので、「検索には出るのに開けない」という症状になる（[Issue #225](https://github.com/SlashNephy/surasura-roppou/issues/225)）。

## Decision

基準日は既定の版を選ぶ機能であり、出題範囲のフィルタではないと定める。基準日時点に版が無い法令は現行法として表示し、基準日の対象外である旨を書誌情報に添える。

版が存在する法令については従来どおり基準日時点の版を返す。

## Consequences

- `loadLawViewerDocument` は基準日付き 404 のとき現行法を取り直し、`baseDateFallback` を立てて表示する。取得できない場合のみエラーにする。
- フォールバック表示は実体が現行法なので、保存メタは `isCurrent: true` とする。
- 基準日は「取得できる版が無ければ表示を止める」機能ではなくなる。出題範囲を厳密に絞りたい要求が出た場合は、別の設定として設計する。
```
